STEALTH BOX
Твой tmux. Твои вкладки. Агенты на ВМ.
01 / Идея

Твой tmux остаётся.
Агенты работают на ВМ.

Как на твоём скриншоте: несколько окон tmux, привычные цвета и горячие клавиши. В каждом окне — отдельное подключение к нужному агенту на ВМ.

Твой MacТерминал + твой локальный tmux
→
Твоя ВМОтдельные процессы агентов · код · Git
Иллюстрация твоего локального tmux · существующее оформление сохраняется
 agent-hub  1   │   pagent  2   │   another-project  3 
Окно 1 → Codex на ВМ → проект agent-hub
Окно 2 → Codex на ВМ → проект pagent
Окно 3 → Claude на ВМ → another-project
Презентация объясняет первую CLI-версию и планируемое развитие. Здесь нет настоящего подключения к ВМ.
02 / Уже работает

Одна команда — и ты в сессии.

Терминал на Mac
$ stealthbox open --project example --runner vm -- codex

Mac ── SSH ──► ВМ ──► tmux ──► Codex
Реализовано

В том же терминале

Программа подключается по SSH и создаёт или открывает tmux-сессию. Codex запускается командой после «--».

Реализовано

Или обычная консоль

Выбираешь --session shell. Без команды агента открывается оболочка для обычной работы.

Перед первым запуском нужны SSH-доступ, пути проекта и установленный на ВМ агент. Отдельное окно приложения пока не создаётся.

03 / Кто где работает

Терминал — на Mac.
Рабочая сессия — на ВМ.

На твоём Mac

  • Окно терминала, шрифты и цветовая схема.
  • Твой локальный tmux: окна, панели и горячие клавиши.
  • Программа Stealth Box.
  • Docker, если выбрал локальный прогон.

На твоей ВМ

  • Процесс Codex или другого агента.
  • Основной рабочий каталог и Git.
  • Docker для прогонов на ВМ.
  • При необходимости — скрытая tmux-сессия для сохранения процессов.
При обрыве SSH tmux продолжает работать на ВМ. При остановке самой ВМ процессы завершаются — потребуется возобновить работу.

05 / Зачем различать агентов
Несколько окон.
Отдельный агент в каждом.
Сейчас
Локальные окна уже разделены
Твой tmux на Mac
├─ окно 1 → Codex / agent-hub
├─ окно 2 → Codex / pagent
└─ окно 3 → Claude / another-project
Каждое локальное окно может открыть своё SSH-подключение. Сейчас это запускается вручную. Скрытые удалённые сессии тоже должны различаться, чтобы повторное подключение вернуло именно нужный процесс.
Планируем исправить
Stealth Box создаёт нужное окно
example-codex-vm
└─ Codex

example-claude-vm
└─ Claude
Проект, агент и имя рабочей сессии определяют подключение. Программа создаёт окно в твоём локальном tmux. Удалённая служебная сессия не должна добавлять вторую видимую панель tmux.


06 / Прогон на Mac
Файлы туда.
Вывод — обратно в терминал.
1
Агент меняет код в основном каталоге на ВМ.
2
stealthbox run синхронизирует код в отдельный каталог Mac, включая незакоммиченные изменения.
3
На Mac запускается команда Docker. Вывод и код завершения возвращаются в терминал.
Реализовано при настроенном SSH
$ stealthbox run -- \
  docker compose run --rm test

ВМ: рабочий код
    │ rsync
    ▼
Mac: отдельный каталог → Docker
    │ вывод + результат
    ▼
Твоя сессия на ВМ
Stealth Box нужно установить и настроить на ВМ. ВМ должна иметь SSH-доступ к Mac. Агенту задаётся правило вызывать прогоны через Stealth Box; произвольные Docker-команды не перехватываются.
