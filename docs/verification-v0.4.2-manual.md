# Ручная проверка v0.4.2 — 2 октября 2026

Подтверждены перенос исходников между Mac и Linux ВМ с внутренними ссылками,
подготовка отдельного QA-стека Zadolbator и все suites четырёх PHP-приложений.
После исправления подготовки стенда подтверждены 1264 теста и 5557 assertions:
1262 теста прошли, 2 остались incomplete, failures/errors нет.
Финальные артефакты выгружены и сверены; собственный QA-стек удалён с сохранением
отчётов и остальных Docker-ресурсов. Инструкция повторения —
[проверка Zadolbator](zadolbator-manual-test.md).

  к моделям не проверены; авторизация и личные конфиги не перезаписывались.

## QA: ВМ → Mac RunnerRoot → Docker

Запущен `tools/zadolbator-qa.sh prepare` через `stealthbox run --runner local`.
Все три сервиса получили healthy. В Development-базе и отдельной test-базе
успешно выполнены по 377 миграций.

| Набор | Tests | Assertions | Статус |
|---|---:|---:|---|
| common/unit | 1125 | 5225 | exit 0, 2 incomplete |
| api | 105 | 239 | Полный повтор exit 0, failures/errors 0 |
| frontend | 8 | 15 | Полный повтор exit 0 |
| backend: unit + functional | 26 | 78 | Полный повтор exit 0, failures/errors/skipped 0 |
| Всего | 1264 | 5557 | 1262 passed, 2 incomplete, failures/errors 0 |

Два incomplete не считаются успешно выполненными тестами.
Через настоящий `fetch` скачаны 14 артефактов Mac → ВМ: 4 XML, 4 log и 6 fail HTML.
После копирования обратно на Mac SHA-256 совпали. Первоначальный отрицательный
backend-результат сохранён. Затем в отдельную папку
`~/.stealthbox/qa-v0.4.2-20261002/artifacts-final` на ВМ скачаны финальные 4 XML,
4 log, `prepare.log` и `clickhouse-prepare.log`. Все 10 SHA-256 совпали после
копирования обратно на Mac; скачанные XML подтвердили итоговые числа без failures/errors.
Затем `down` через ВМ завершился с exit 0: удалены три собственных контейнера,
внутренняя сеть, два named volumes и принадлежащий Redis anonymous volume.
Последующий `status` через ВМ вернул пустую таблицу и exit 0. По меткам QA
контейнеров, сетей и volumes не осталось. Сравнение сохранённых ID подтвердило,
что все 42 посторонних контейнера, 17 сетей и 19 volumes сохранились.
Все 10 отчётов сохранили SHA-256 после `down` и дополнительной синхронизации
при `status`; `vendor/autoload.php` также сохранился. Постоянная ВМ не удалялась.
Helper хранит отчёты и копии обычных файлов fail HTML в `.stealthbox-qa/reports`.

## Найденные ошибки подготовки

1. Явный `platform: linux/amd64` отклонял существующий локальный image,
   несмотря на подтверждённые метаданные AMD64. Убран параметр платформы из QA
   Compose; сохранились проверка метаданных и `pull_policy: never`. Реальный
   PHP smoke и последующий `prepare` прошли. Образ не пересобирался.
2. В импортированной папке без `.git` выбор проекта останавливался на `itfinance`,
   а helper получал вложенную рабочую директорию и отказывался запускаться.
   Для свежей копии создан Git-корень; этот шаг добавлен в инструкцию.
3. `.stealthbox-qa` первоначально удалялась при следующей синхронизации runner.
   Путь зарезервирован для обоих транспортов. Регрессии на реальном локальном
   rsync и `SyncSnapshot` подтверждают сохранение отчёта с теми же inode/mtime,
   исключение конфликтующего source state и удаление устаревшего обычного кода.
4. Явное имя suite ограничивало API/backend и выбирало пустой frontend/unit. Helper теперь
   запускает все suites выбранного приложения; XML без `testcase` при exit 0
   считается ошибкой. Первый API дал только 51 тест / 130 assertions;
   frontend — пустой XML при exit 0; backend — только 16 unit-тестов.
   Полные API/frontend повторно прошли; полный backend выявил ошибку стенда ниже.
5. Все шесть failures `StatDatePeriodsSmokeCest` получили HTTP 200, но без дат
   в grid. Сохранённые HTML содержат alert с `UNKNOWN_TABLE` для
   `zb-message_queue_wide-cmt`. Тесты используют настоящую ClickHouse-схему,
   а prepare создал только PG-схему. Добавлено извлечение QA-only DDL пустой таблицы
   из канонической миграции `m240202_043836_create_zb_message_queue_wide_cmt_table`
   выбранного checkout; SQL хранится только в закрытой `.stealthbox-qa`.
   Генератор выполнен в PHP 7.4, DDL применён через собственный ClickHouse-сервис.
   Все шесть прежних failures прошли; полный backend дал 26 тестов / 78 assertions,
   exit 0. Первоначальный результат: 26 тестов / 63 assertions, 6 failures, 0 errors.
   Причина подтверждена как подготовка свежего стенда; продуктовый дефект не подтверждён.
6. Повторный pull остановился до исполнения helper: macOS rsync с `--no-links`
   оставил dangling receiver-ссылку Yii assets на `/app/vendor/...` и не смог
   удалить родительский каталог (`Directory not empty`, exit 23). Это не ошибка
   ownership: каталог и ссылка принадлежат пользователю Mac. Добавлена очистка
   только незащищённых ссылок disposable runner после проверки размера источника,
   через anchored `os.Root.Remove`; цели ссылок и защищённые caches/state не трогаются.
   Настоящий `/usr/bin/rsync` воспроизвёл сбой в regression, затем прошёл после
   очистки. После установки обновлённых бинарников и перезапуска bridge живой
   pull ВМ → Mac и полный backend прошли без exit 23.
   Ошибки pull теперь включают ограниченный stderr для диагностики.
