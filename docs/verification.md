# Проверка v0.2.0

Проверено на macOS с Docker Desktop и изолированным Linux-контейнером,
который выполняет роль ВМ с настоящими sshd и tmux.

- Go: тесты с race detector, `go vet`, сборки Darwin/Linux × ARM64/AMD64.
- Настоящий TUI через PTY: создание проекта, сохранение настроек моста,
  выход по Esc и восстановление режима терминала.
- SSH: установка бинарника и конфигурации, отдельные окна агентов,
  перенос tmux-настроек, восстановление подключения без повторного запуска агента.
- Обратный Unix socket: авторизация, восстановление туннеля, работа после detach,
  завершение выполняемой команды при остановке сервиса.
- Снимок незакоммиченных файлов с Linux на Mac и настоящий Docker Compose
  с bind mount; исключение `.env`, передача stdout/stderr и ненулевого exit code.
- Выполнение команды на Mac и скачивание артефакта обратно на Linux.
- Проверки обхода путей, symlink, размера архива, защиты каталога исполнителя
  и привязки MCP к выбранному проекту.
- Локальный Codex CLI принимает временные MCP-overrides без изменения его
  пользовательской конфигурации.

В интеграционном тесте Codex/Claude заменены процессами-заглушками. Реальные
запросы к моделям, авторизация агентов и перенос конкретных пользовательских
tmux-плагинов не проверялись.

## Облачный прогон — 2 октября 2026

После авторизации выполнен полный прогон на временной ВМ Yandex Cloud
Kazakhstan, зона `kz1-a`, платформа `standard-v3`, Ubuntu 24.04, 4 vCPU,
8 ГБ RAM. Диск для теста — SSD 20 ГБ: создание SSD 80 ГБ было отклонено
из-за квоты. Это функциональная проверка, а не нагрузочный тест.

Прошли проверки:

- SSH с отдельным временным ключом и закреплённым ключом хоста; входящий
  порт 22 ограничен текущим внешним IP, сервисного аккаунта у ВМ нет.
- Установка Stealth Box, удалённый tmux, отдельные окна Codex/Claude-заглушек
  и настройки оформления.
- Снимок файлов с ВМ в отдельный каталог Mac и настоящий Docker Compose
  с bind mount; `.env` не переносится.
- Тот же Docker Compose непосредственно на казахстанской ВМ.
- Команда на Mac через обратный Unix socket, передача exit code 7.
- Принудительный обрыв SSH: клиент и обратный туннель восстанавливаются,
  процесс агента не запускается повторно.
- Работа моста после detach из tmux и скачивание артефакта с Mac на ВМ.

Рабочие проекты и пользовательские ключи агентов на ВМ не копировались.
Другие облачные регионы не использовались.

После прогона удалены временная ВМ, её загрузочный диск и тестовая группа
доступа. Удаление подтверждено повторными запросами списка ресурсов.
Публичный IP был динамическим и освобождён вместе с ВМ. Фоновый мост на Mac
остановлен, временные ключи, настройки и каталог исполнителя удалены.

Воспроизведение: `make test`, `python3 tests/integration/tui.py`, `make e2e`.
GitHub Actions повторяет проверки на Ubuntu и macOS.

## Сборки v0.2.1 для трёх систем

Собраны macOS/Linux/Windows × AMD64/ARM64. Windows — нативный `.exe`-лаунчер
для WSL 2 с обоими Linux-бинарниками внутри; Unix-сокеты, SSH и TUI работают
в выбранном Linux-дистрибутиве. Для сборки из исходников сначала выполните
`make windows-payload VERSION=v0.2.1`, затем собирайте Windows-лаунчер.

Проверены Go-тесты с race detector и vet на macOS/Linux, форматы всех шести
бинарников и SHA-256. Скрипты установки и запуска WSL-лаунчера проверены
в настоящем Linux-контейнере, включая передачу пути с пробелами.
Windows CI проверяет встроенные ELF-бинарники, выбор дистрибутива, сборку
`.exe`, запуск `--version` и `--help`. Полный интерактивный сеанс в WSL 2
на пользовательской Windows-машине отдельно не проверялся.
